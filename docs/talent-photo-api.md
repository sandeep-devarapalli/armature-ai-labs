# Talent profile photo API — local release candidate

`talent-profile-photo?profile_id=ID`: GET public consented directory image; GET with `source=membership` and bearer token previews the owner's private membership image. POST with bearer token and JSON `{use_membership_photo:true,consent_version:"2026-10-13-public-photo-v1"}` copies the current member avatar, otherwise latest unexpired registration photo (never identity documents). Alternatively POST JPEG/PNG bytes with `x-photo-consent: 2026-10-13-public-photo-v1`, maximum 5 MiB. DELETE removes directory photo consent immediately without modifying membership originals. POST returns `{saved:true,photoVersion:UUID}`; DELETE returns `{removed:true}`.

Only approved owners of published, claimed profiles may publish. Changes are serialized using operation tokens and profile locks; ownership is checked again after scanning. Photo version is server controlled and ordinary profile patches reject it. Public GET checks current ownership, publication and consent before and after download. Images reside in private `talent-profile-photos`; public API returns bytes, never object paths or storage signed URLs. Responses use no-store and nosniff.

Both copied and uploaded images require existing onboarding image scanner success. No automatic photo publication occurs on claim or registration. Queued abandoned/replaced/removed objects require retention processing before release. Production publication and scanner/retention readiness remain separate.

The UI saves the exact bytes shown in the private membership preview through the scanned raw-upload endpoint. This avoids publishing a changed source image after consent. Cleanup is integrated in onboarding-retention behind TALENT_PHOTO_CLEANUP_ENABLED, shares its 100-item bound and requires the existing retention job authorization. Finish locks an unexpired reservation; cleanup skips locked rows. Operational scanner/storage and scheduled cleanup still require release validation.
